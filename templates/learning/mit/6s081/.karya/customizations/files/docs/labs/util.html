Exercise 1: sleep (easy)

Implement the Unix program sleep for xv6. Your sleep should pause for a user-specified number of ticks. A tick is a concept defined by the xv6 kernel, namely the time between two interrupts from the timer chip.

File: user/sleep.c

Requirements

  • If the user forgets to pass an argument, print an error message.
  • The command-line argument is passed as a string; convert it to an integer using atoi (see user/ulib.c).
  • Use the system call sleep.
  • See user/echo.c, user/grep.c, and user/rm.c for examples of using command-line arguments.
  • Add your program to UPROGS in Makefile.
  • The main xv6 C library is in user/ulib.c, user/printf.c, and user/umalloc.c.

Test

Exercise 2: pingpong (easy)

Write a program that uses UNIX system calls to "ping-pong" a byte between two processes over a pair of pipes, one for each direction. The parent should send a byte to the child; the child should print "<pid>: received ping", where <pid> is its process ID, write the byte on the pipe to the parent, and exit; the parent should read the byte from the child, print "<pid>: received pong", and exit.

File: user/pingpong.c

Requirements

  • Use pipe to create a pipe.
  • Use fork to create a child.
  • Use read to read from the pipe, and write to write to the pipe.
  • Use getpid to find the process ID of the calling process.
  • Add the program to UPROGS in Makefile.
  • xv6 user programs have a limited set of library functions available to them. See user/user.h.

Expected output

$ pingpong
4: received ping
3: received pong
$

Test

./grade-lab-util pingpong

Exercise 3: primes (moderate/hard)

Write a concurrent version of prime sieve using pipes. Use the design from the Unix pipeline described here (the picture in the middle of the page). Your solution should be in the file user/primes.c.

File: user/primes.c

Requirements

  • Arrange for the main process to feed the numbers 2 through 35 into the pipeline.
  • Create a process per prime. Communicate through pipes.
  • Close file descriptors that a process doesn't need, otherwise your program will run xv6 out of resources before reaching 35.
  • Once the first process reaches 35, it should wait until the entire pipeline terminates, including all children, grandchildren, etc. So the main primes process should only exit after all the output has been printed, and after all the other primes processes have exited.
  • Use read to return zero when the write-side of a pipe is closed.
  • Write 32-bit (4-byte) ints directly into pipes rather than using formatted ASCII I/O.
  • Only create the processes in the pipeline as they are needed.

Expected output

$ primes
prime 2
prime 3
prime 5
prime 7
prime 11
prime 13
prime 17
prime 19
prime 23
prime 29
prime 31
$

Test

./grade-lab-util primes

Exercise 4: find (moderate)

Write a simple version of the UNIX find program: find all the files in a directory tree with a specific name.

File: user/find.c

Requirements

  • Look at user/ls.c to see how to read directories.
  • Use recursion to allow find to descend into sub-directories.
  • Don't recurse into "." and "..".
  • Changes to the file system persist across xv6 runs; to get a clean file system run make clean and then make qemu.
  • Use strcmp().
  • Add the program to UPROGS in Makefile.

Expected output

$ echo > b
$ mkdir a
$ echo > a/b
$ find . b
./b
./a/b
$

Test

./grade-lab-util find

Exercise 5: xargs (moderate)

Write a simple version of the UNIX xargs program: its arguments describe a command to run, and it reads additional arguments from standard input, one per line, then runs the command with the original arguments combined with the additional per-line arguments.

File: user/xargs.c

Requirements

  • Use fork and exec to invoke the command on each line of input. Use wait in the parent to wait for the child to complete before reading the next line of input.
  • To read individual lines of input, read a character at a time until a newline ('\n') appears.
  • kernel/param.h declares MAXARG, which may be useful if you need to declare an argv array.
  • Add the program to UPROGS in Makefile.
  • Changes to the file system persist across xv6 runs; to get a clean file system run make clean and then make qemu.
  • xargs, find, and grep combine well: 
    $ find . b | xargs grep hello
    will run grep hello on each file named b in the directories below ".".
  • To test your solution for xargs, run the shell script xargstest.sh. Your solution is correct if it produces the following output:
$ sh < xargstest.sh
$ $ $ $ $ $ hello
hello
hello
$ $

Optional challenges

  • Write an uptime program that prints the uptime in ticks using the uptime system call.
  • Support regular expressions in name matching for find. grep.c has some primitive support for regular expressions.
  • The xv6 shell (user/sh.c) does not implement many features present in real shell. Add an if statement, while loops, or sub-shells. Or make the shell use threads rather than processes. Add tab completion.
